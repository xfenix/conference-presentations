# Внешние петли для агента: сравнение

Дата проверки: 3 октября 2026. Внешняя петля запускает агента и решает, когда остановиться.

## 1. `/loop` в Claude Code

- Что это: встроенный скилл, повторяет prompt или slash-команду внутри открытой сессии.
- Когда появилось: v2.1.71, «Added `/loop` command to run a prompt or slash command on a recurring interval». В npm — 6 марта 2026. Источник: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- Режимы: `/loop 5m <prompt>` — фиксированный интервал через cron. `/loop <prompt>` без интервала — Claude сам выбирает паузу от 1 минуты до 1 часа. `/loop` без всего — встроенный prompt обслуживания или `loop.md`. Источник: https://code.claude.com/docs/en/scheduled-tasks
- Лучший случай: опрос в ходе работы — деплой, CI, комментарии к PR.
- Ограничение: живёт только в открытой сессии на вашей машине. Минимальный интервал 1 минута. Повторяющаяся задача удаляется через 7 дней.
- Условие остановки: вы отменяете, или Claude решает, что работа сделана, или истекли 7 дней.
- Рядом: `/goal` (v2.1.139, 11 мая 2026). Следующий ход стартует сразу после предыдущего, а отдельная модель после каждого хода проверяет заданное условие. Источник: https://code.claude.com/docs/en/goal

## 2. Ralph

- Что это: bash-цикл, который заново подаёт агенту один и тот же prompt. `while :; do cat PROMPT.md | claude-code ; done`.
- Автор и дата: Geoffrey Huntley, пост «Ralph Wiggum as a "software engineer"», 14 июля 2025. Источник: https://ghuntley.com/ralph/
- Идея: память между итерациями — в файлах и git, а не в контексте. Каждая итерация начинает с чистого контекста.
- Плагин Anthropic `ralph-wiggum`: добавлен в репозиторий claude-code 16 ноября 2025. Команды `/ralph-loop "<prompt>" --max-iterations N --completion-promise "<текст>"` и `/cancel-ralph`. Работает через Stop hook: блокирует выход и подаёт тот же prompt снова, внутри текущей сессии. Источник: https://github.com/anthropics/claude-code/tree/main/plugins/ralph-wiggum
- Huntley на своей странице прямо пишет, что плагин для Claude Code — «не то». Подробности он даёт в видео, мы их не проверяли.
- Лучший случай: долгая работа с нуля, где результат проверяется тестами.
- Ограничение: сам цикл не останавливается. Без лимита итераций он жжёт токены, ошибки исправляются правкой prompt.
- Условие остановки: в чистом виде — никакого, только Ctrl+C. В плагине — фраза-обещание в ответе или `--max-iterations`. По умолчанию итерации не ограничены.

## 3. Workflows в Claude Code

- Что это: скрипт на JavaScript, который пишет Claude и который запускает в фоне десятки и сотни субагентов.
- Когда появилось: v2.1.154, 28 мая 2026, research preview. Ключевое слово `ultracode` с v2.1.160. Подробно: [research-workflows-tooling.md](research-workflows-tooling.md)
- Лучший случай: большая задача, которая делится на независимые части. Например, аудит всех эндпоинтов или массовая миграция.
- Ограничение: дорого по токенам. Пока research preview.
- Условие остановки: скрипт дошёл до конца. Ход и остановку задаёт код, а не модель.

## 4. Запуск по расписанию и в облаке

### Routines и `/schedule` (Claude Code)

- Что это: сохранённый prompt с репозиториями и коннекторами. Выполняется в облаке Anthropic как отдельная сессия Claude Code.
- Запуск: по расписанию, по HTTP POST или по событию GitHub. Создаются на claude.ai/code/routines или командой `/schedule` в CLI. Статус — research preview. Планы Pro, Max, Team, Enterprise. Источник: https://code.claude.com/docs/en/routines
- Лучший случай: регулярная работа без человека. Ночной разбор бэклога, ревью новых PR, проверка после деплоя.
- Ограничение: минимальный интервал 1 час. Каждый запуск работает со свежим клоном, без локальных файлов. MCP-серверы из локального Claude Code к routine не подключить, только коннекторы (v2.1.251). Работает без запросов разрешений.
- Условие остановки: каждый запуск идёт до конца одной сессии. Расписание действует, пока routine не выключат.

### GitHub Actions: `anthropics/claude-code-action`

- Что это: action, который запускает Claude Code в CI на `@claude`, на назначение issue или с явным prompt.
- v1 выпущен 26 августа 2025. Источник: https://github.com/anthropics/claude-code-action
- Лучший случай: команда уже живёт в GitHub, нужен агент на событиях PR и issue.
- Ограничение: только GitHub. Каждый запуск — отдельная задача CI без памяти о прошлых запусках.
- Условие остановки: одна сессия на одно событие плюс таймаут задачи CI.

### Codex: scheduled tasks

- В документации OpenAI это сейчас «Scheduled tasks». Повторяющиеся задачи в фоне. В desktop-приложении могут работать в каталоге проекта или в отдельном worktree. Компьютер должен быть включён. Источник: https://developers.openai.com/codex/app/automations
- Это аналог routines и desktop-задач Claude. Подробно мы его не разбирали.

## 5. Свой агент на SDK

- Что это: цикл агента внутри вашей программы на Python или TypeScript. Сколько запусков, какие проверки и когда стоп — решает ваш код.
- Claude Agent SDK: лимиты `max_turns` и `max_budget_usd`, по умолчанию оба выключены. При срабатывании результат приходит с подтипом `error_max_turns` или `error_max_budget_usd`. Источник: https://code.claude.com/docs/en/agent-sdk/agent-loop
- OpenAI Agents SDK: `Runner.run` крутит цикл, пока модель не выдаст финальный ответ без вызовов инструментов. Превышение `max_turns` даёт исключение `MaxTurnsExceeded`. Источник: https://openai.github.io/openai-agents-python/running_agents/
- Лучший случай: свой продукт или конвейер, где нужны своя проверка готовности, логирование и интеграции.
- Ограничение: весь harness — на вас: права, повторы, память, наблюдаемость.
- Условие остановки: любое, какое напишете. Например, тесты зелёные плюс лимит ходов и бюджета.

## Сводная таблица

| Петля | Где работает | Кто решает, что пора стоп |
| :- | :- | :- |
| `/loop` | открытая сессия, ваша машина | вы, Claude или истечение 7 дней |
| `/goal` | открытая сессия | отдельная модель проверяет условие |
| Ralph (bash) | ваш терминал | никто, только Ctrl+C |
| Плагин ralph-wiggum | сессия, Stop hook | фраза-обещание или лимит итераций |
| Workflows | фон, субагенты | код скрипта |
| Routines, `/schedule` | облако Anthropic | конец сессии, расписание повторяет |
| claude-code-action | GitHub Actions | конец задачи CI |
| Свой SDK-агент | ваш код | ваш код, `max_turns`, бюджет |

## Вывод (наш, не из источников)

- По умолчанию разработчику подходит то, что встроено в сессию: `/goal`, когда у задачи есть проверяемый финал, и `/loop`, когда нужно ждать внешнее событие. Основание: документация Claude Code сама разделяет их именно так («next turn starts when» — предыдущий ход закончился или прошёл интервал). Ничего ставить не нужно, остановка встроена.
- Workflows — когда задача делится на много независимых частей и токенов не жалко.
- Routines или GitHub Actions — когда работа регулярная и должна идти без вашего ноутбука.
- Ralph в чистом виде — для экспериментов с нуля под присмотром и с лимитом. Сам цикл не знает, когда остановиться.
- Свой SDK-агент — когда петля становится частью продукта и нужна своя проверка готовности.

## Не проверено

- Дата запуска routines и первой версии `/schedule`: в CHANGELOG первого упоминания с «Added» не нашли.
- Почему Huntley считает плагин ralph-wiggum «не тем»: объяснение только в видео.
- Codex scheduled tasks: прочитали только начало страницы, лимиты и условия остановки не смотрели.

## Для слайда

- `/loop` повторяет запрос по таймеру, пока открыта сессия.
- Ralph — bash-цикл, который сам никогда не останавливается.
- Workflows раздают большую задачу десяткам субагентов по скрипту.
- Routines и GitHub Actions запускают агента в облаке по расписанию или событию.
- По умолчанию берите `/goal` или `/loop`, а свой SDK — для продукта.
