Основные принципы

  • Соблюдать PEP8, PEP257, PEP484, PEP526
  • Длина строки до 120 символов
  • Импорты встроенных библиотек целиком
  • Более 2 импортов из модуля — импортировать весь модуль
  • Покрывать 100% кода аннотациями типов

Типизация

  • Скалярные типы выводятся mypy автоматически
  • Максимум сужения типов
  • Используем typing.Final для констант
  • TypedDict для сложных структур
  • dict с Literal для максимально точной типизации

                    import typing

                    SOME_CONST: typing.Final[
                        dict[typing.Literal['what', 'kek'], typing.Literal[5, 'raz']]
                    ] = {
                        'what': 5,
                        'kek': 'raz',
                    }

Обращения по индексам и ключам

  • item[0] и item[«key»] будут падать — обрабатывать try-except
  • Использовать get для словарей при необходимости
  • Иерархия ошибок: LookupError → IndexError/KeyError
  • Проверять ключи через in вместо перехвата исключений

Исключения

  • Использовать конкретные классы ошибок
  • Сужать количество строк внутри try
  • Проверять условие лучше, чем ловить исключение
  • Exception только в исключительных случаях

Именование

  • Имена переменных и функций ≥8 символов
  • Использовать осмысленные названия
  • Функции называют глаголами

Неизменяемость

  • Переменные — typing.Final
  • Классы — typing.final
  • Словари — types.MappingProxyType
  • Использовать dataclasses с frozen и slots
  • Минимизировать изменение состояния

Инверсия условий

  • Использовать early return
  • Минимизировать вложенность if
  • Пример: проверить исключение вместо ловли
  • Упрощает чтение и поддержку

                    def process_something_important(user_payload):
                        if not user_payload:
                            print("No data")
                            return
                        if not isinstance(user_payload, list):
                            print("Invalid data")
                            return
                        if not all(isinstance(some_index, int) for some_index in user_payload):
                            print("Invalid list")
                            return

                        print(
                            f"Result: {sum(user_payload)}"
                            if sum(user_payload) > 0
                            else "Sum is non-positive"
                        )

Работа с retry и надежностью

  • Использовать stamina для ретраев
  • Применять к sql, файлам, HTTP, consumer/producer
  • Ограничивать количество попыток и интервал рандомизировать
  • circuit breaker для защиты сервисов
  • Важные операции именовать retry/resilient/robust

Избегать магии

  • Не использовать hasattr/getattr без причины
  • Не создавать временные переменные без смысла
  • Использовать прямые вызовы вместо лишних присвоений

REST

Что такое REST?

Кажется, REST как таковой, слабо достижим

Поэтому

  • Урлы — сущности (что такое сущность?)
  • /rest[-(public|web|mobile|admin|internal)]/[имя-сервиса]/[имя-сущности]/
  • /rpc[-(public|web|mobile|admin|internal)]/[имя-сервиса]/сделай-что-то-что-в-сущность-не-укладывается/
  • Скажем нет вложенности, остальное — query параметры

Версионирование

  • Версия — не часть сущности, поэтому /v1/ скажем нет
  • Версия — метаинформация, а ей место в заголовках
  • accept: application/vnd.some.name+json; version=1.0
  • By default — версионирование мешает, лучше без него
  • Когда точно нужно: мобила, неконтролируемые клиенты
